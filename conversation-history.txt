  Prerequisites:
  1. Create a PayPal sandbox account at developer.paypal.com — you need a
  Sandbox merchant and a Sandbox buyer account.
  2. Add to your packages/dev-server/.env:
  PAYPAL_CLIENT_ID=<your sandbox client ID>
  PAYPAL_CLIENT_SECRET=<your sandbox client secret>
  PAYPAL_ENVIRONMENT=sandbox
  3. In the Vendure Admin UI, create a Payment Method with code paypal (Settings
  → Payment Methods → Create).
  4. Start the dev server: npm run dev:server from packages/dev-server.

  Step 1 — Register a shop session and add a product to cart

  POST http://localhost:3000/shop-api
  Content-Type: application/json

  {
    "query": "mutation { addItemToOrder(productVariantId: 1, quantity: 1) { ...
  on Order { id code totalWithTax } } }"
  }
  Copy the session cookie (or bearer token) from the response headers. Use it on
  all subsequent requests.

  Step 2 — Create the PayPal order

  POST http://localhost:3000/shop-api
  Content-Type: application/json
  Cookie: <session cookie from step 1>

  {
    "query": "mutation { createPaypalOrder { paypalOrderId approvalUrl } }"
  }

  Expected response:
  {
    "data": {
      "createPaypalOrder": {
        "paypalOrderId": "XXXXXXXXXXXXXXXXX",
        "approvalUrl": "https://www.sandbox.paypal.com/checkoutnow?token=XXXXXX"
      }
    }
  }

  Step 3 — Approve the order as the sandbox buyer

  Open the approvalUrl in a browser and log in with your sandbox buyer account.
  Click "Pay Now". PayPal will redirect back to your return URL (which may 404 —
  that's fine, the order is approved).

  Step 4 — Capture the payment via addPaymentToOrder

  POST http://localhost:3000/shop-api
  Content-Type: application/json
  Cookie: <session cookie>

  {
    "query": "mutation AddPayment($input: PaymentInput!) {
  addPaymentToOrder(input: $input) { ... on Order { id state totalWithTax
  payments { id state transactionId amount metadata } } ... on
  OrderPaymentStateError { errorCode message } ... on PaymentFailedError {
  errorCode message paymentErrorMessage } } }",
    "variables": {
      "input": {
        "method": "paypal",
        "metadata": {
          "paypalOrderId": "<paypalOrderId from step 2>"
        }
      }
    }
  }

  Expected correct response:
  {
    "data": {
      "addPaymentToOrder": {
        "id": "...",
        "state": "PaymentSettled",
        "payments": [{
          "state": "Settled",
          "transactionId": "<PayPal capture ID>",
          "metadata": {
            "paypalOrderId": "...",
            "captureId": "...",
            "paypalStatus": "COMPLETED"
          }
        }]
      }
    }
  }

  The key success signals: payment.state = "Settled", payment.transactionId
  contains a PayPal capture ID (starts with a capital letter, ~17 chars), and
  metadata.paypalStatus = "COMPLETED".

  Copy that token value.

  Steps 2, 3, 4 — Pass it as a Bearer token on every subsequent request:

  Add this header to all remaining Postman requests:
  Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

  So for Step 2 (createPaypalOrder):
  POST http://localhost:3000/shop-api
  Content-Type: application/json

  instruction with this Authorization: Bearer header on each request.

  If you don't see a vendure-auth-token header either, check that you're looking
  at the Response headers (not request headers) in Postman's response panel
  after the addItemToOrder call.

> Step 4 – Retry a failed payment:

● When a scheduled billing cycle fails (e.g. the customer's card is declined or
  has insufficient funds), PayPal marks the subscription with an outstanding 
  balance. The subscription stays active but that cycle's payment is unpaid.

  retryPaypalSubscriptionPayment calls PayPal's Capture authorized payment on
  subscription (https://developer.paypal.com/docs/api/subscriptions/v1/#subscrip
  tions_capture) endpoint (POST /v1/billing/subscriptions/{id}/capture) to
  manually collect that outstanding balance — it's the merchant saying "try
  charging this subscriber again right now."

  When you'd use it:

  1. PayPal auto-charges the customer on their billing cycle → card declined
  2. PayPal retries automatically up to the plan's paymentFailureThreshold (we
  set it to 3 in createBillingPlan)
  3. All automatic retries fail → the subscription gets suspended or the cycle
  remains unpaid
  4. Customer updates their payment method and tells support "please try again"
  5. Merchant runs retryPaypalSubscriptionPayment to immediately capture the
  outstanding amount rather than waiting for the next scheduled retry

  The amount and currencyCode args:

  PayPal requires you to specify the amount explicitly for a manual capture —
  it's typically the same as the subscription cycle price, but could be a
  different value if the merchant negotiated a partial collection. currencyCode
  must match the subscription's currency (e.g. "USD").

  In practice for most merchants the call is straightforward:
  mutation {
    retryPaypalSubscriptionPayment(
      subscriptionId: "I-XXXXXXXX"
      amount: "9.99"
      currencyCode: "USD"
      note: "Customer updated payment method — retrying May cycle"
    )
  }

    }
  }

● This is a known PayPal Sandbox limitation — the buyer account UI in sandbox
  does not render shipment tracking the same way production does. The API call
  still works, but the sandbox buyer interface doesn't show the tracking panel.

  Here's how to confirm the tracking was actually pushed successfully:

  1 — Check server logs

  When the fulfillment transitions to Shipped, you should see these log lines in
  your dev server output:

  [PaypalPlugin] [verbose] Pushing shipment tracking to PayPal for order <code>
  — paypalOrder=..., capture=..., carrier=UPS, tracking=1Z999AA...
  [PaypalPlugin] [verbose] Shipment tracking pushed to PayPal for order <code>.

  If you see an [error] line instead, it means the API call failed and will tell
  you why.

  ---
  2 — Verify via the PayPal Orders API (Admin API query)

  You can confirm the tracking was recorded by fetching the PayPal order and
  checking its purchase unit:

  # This isn't exposed as a query yet, but you can test it directly in Postman.
  # GET https://api-m.sandbox.paypal.com/v2/checkout/orders/<paypalOrderId>
  # Authorization: Bearer <access-token>

  The response will include a trackers array under the purchase unit if tracking
  was successfully attached:
  {
    "purchase_units": [{
      "payments": {
        "captures": [{
          "id": "...",
          "status": "COMPLETED"
        }]
      }
    }],
    "trackers": [{
      "id": "<captureId>-<trackingNumber>",
      "status": "SHIPPED",
      "tracking_number": "1Z999AA10123456784",
      "carrier": "UPS"
    }]
  }

  ---
  3 — Check the Merchant dashboard instead of Buyer

  In the PayPal Sandbox merchant account (https://sandbox.paypal.com):
  1. Go to Activity → All Transactions
  2. Find the relevant transaction
  3. Click into the transaction details
  4. Tracking appears under the merchant view, not the buyer view, in sandbox

  account) is only fully rendered in live PayPal accounts, not sandbox. The API
  behavior — recording the tracking against the capture — is identical between
  environments.
